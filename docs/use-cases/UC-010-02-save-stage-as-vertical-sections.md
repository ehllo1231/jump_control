# UC-010-02: 스테이지 캡처를 세로 구간별 이미지로 저장

- 상태: Verified
- 마지막 갱신일: 2026-07-17

## 목적

맵 제작자가 긴 스테이지 전체 캡처를 원하는 개수의 세로 구간으로 나눠 여러 PNG 파일로 저장한다.

## 액터

- 맵 제작자
- 개발자

## 사전 조건

- Unity Editor에서 저장할 스테이지 씬이 열려 있어야 한다.
- 활성 씬에 Orthographic Camera와 활성 Renderer가 하나 이상 있어야 한다.

## 트리거

- 사용자가 `Tools > Jump Timing > Stage Capture`에서 `Vertical Sections`를 2 이상으로 설정하고 캡처 버튼을 누른다.

## 기본 흐름

1. 사용자는 전체 캡처를 나눌 세로 구간 개수 `N`을 입력한다.
2. 시스템은 전체 캡처 높이를 위에서 아래 방향으로 `N`개 구간에 배분한다.
3. 사용자는 결과 PNG들을 저장할 폴더를 선택한다.
4. 시스템은 스테이지 전체를 기존 타일 방식으로 렌더링한다.
5. 시스템은 렌더링 결과를 구간별로 잘라 선택한 폴더에 위에서 아래 순서의 파일명으로 저장한다.
6. 시스템은 저장한 파일 개수, 폴더와 각 이미지의 해상도를 안내한다.

## 대안 및 예외 흐름

- 1a. `N`이 1이면 시스템은 기존과 같이 전체 캡처를 PNG 한 장으로 저장한다.
- 1b. `N`이 1보다 작으면 시스템은 최소값 1로 보정한다.
- 1c. `N`이 전체 이미지 픽셀 높이보다 크면 시스템은 캡처를 시작하지 않고 각 구간이 최소 1픽셀이어야 한다고 안내한다.
- 2a. 전체 높이가 `N`으로 정확히 나누어지지 않으면 시스템은 나머지 픽셀을 위쪽 구간부터 1픽셀씩 배분한다.
- 3a. 사용자가 폴더 선택 대화상자를 취소하면 시스템은 씬과 파일을 변경하지 않고 종료한다.
- 4a. 사용자가 렌더링 진행 창에서 취소하면 시스템은 불완전한 PNG를 저장하지 않고 임시 리소스를 정리한다.
- 5a. 같은 이름의 파일이 이미 있으면 시스템은 기본 파일명에 일련번호를 추가해 기존 파일을 덮어쓰지 않는다.
- 5b. 인코딩 또는 저장 중 오류가 발생하면 시스템은 이번 실행에서 생성한 결과 파일을 정리하고 오류를 Console에 기록한다.

## 인수 조건

- [x] `Vertical Sections`에 1 이상의 정수를 입력할 수 있다.
- [x] `N=1`이면 전체 캡처와 같은 PNG 한 장이 생성된다.
- [x] `N>1`이면 전체 세로 길이가 누락이나 중복 없이 위에서 아래로 `N`개의 PNG에 나뉜다.
- [x] 분할 이미지의 너비는 모두 전체 캡처 너비와 동일하다.
- [x] 파일명은 `part-01-of-03`처럼 위에서 아래 순서를 식별할 수 있다.
- [x] 사용자가 선택한 폴더에 모든 결과 파일이 저장된다.
- [x] 기존 씬 오브젝트, 카메라, Collider와 Transform의 저장된 값이 변경되지 않는다.

## 구현 메모

- `Assets/Editor/StageCaptureWindow.cs`에서 기존 캡처 렌더링 결과를 구간별 PNG로 인코딩한다.
- 전체 RGB24 버퍼의 픽셀 행을 직접 복사하므로 구간 경계에서 재렌더링 오차나 중복이 생기지 않는다.
- 전체 높이를 `N`으로 나눈 나머지는 위쪽 구간부터 1픽셀씩 배분하고, `part-01-of-03`부터 위→아래 순서로 저장한다.
- 저장 전 같은 파일명이 있는지 확인하며, 충돌 시 기본 이름에 `-2`, `-3` 일련번호를 붙인다.
- 현재 Stage 1을 너비 512px·타일 높이 384px·2x MSAA로 캡처해 `N=1`의 `512 × 1793` 한 장과 `N=3`의 `512 × 598`, `512 × 598`, `512 × 597` 세 장을 생성했다. 세 분할 이미지의 모든 픽셀을 한 장 이미지와 대조해 위→아래 순서, 전체 높이, 경계 픽셀이 정확히 일치하는 것을 확인했다.
- Unity 6000.3.1f1 에디터 어셈블리 컴파일을 통과했다.

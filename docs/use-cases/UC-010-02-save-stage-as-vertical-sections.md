# UC-010-02: 스테이지 캡처를 세로 구간별 이미지로 저장

- 상태: Verified
- 마지막 갱신일: 2026-07-19

## 목적

맵 제작자가 긴 스테이지의 실제 미리보기를 보면서 원하는 위치에 분할선을 배치하고, 각 세로 구간을 여러 PNG 파일로 저장한다.

## 액터

- 맵 제작자
- 개발자

## 사전 조건

- Unity Editor에서 저장할 스테이지 씬이 열려 있어야 한다.
- 활성 씬에 Orthographic Camera와 활성 Renderer가 하나 이상 있어야 한다.

## 트리거

- 사용자가 `Tools > Jump Timing > Stage Capture`를 열고 스테이지 미리보기에서 하나 이상의 분할선을 배치한다.

## 기본 흐름

1. 시스템은 현재 캡처 영역을 저해상도 이미지로 렌더링해 창 안에 세로 스크롤 가능한 미리보기를 표시한다.
2. 사용자는 미리보기에 가로 분할선을 추가하고 원하는 세로 위치로 이동한다.
3. 시스템은 각 분할선 사이를 위에서 아래 순서의 구간으로 표시하고 예상 파일 수와 구간별 해상도를 안내한다.
4. 사용자는 분할선을 위아래로 드래그하거나 삭제하고, 필요한 경우 모든 구간을 균등 배치한다.
5. 사용자는 결과 PNG들을 저장할 폴더를 선택한다.
6. 시스템은 스테이지 전체를 기존 타일 방식으로 렌더링한다.
7. 시스템은 렌더링 결과를 사용자가 지정한 분할선 위치에서 잘라 선택한 폴더에 위에서 아래 순서의 파일명으로 저장한다.
8. 시스템은 저장한 파일 개수, 폴더와 각 이미지의 해상도를 안내한다.

## 대안 및 예외 흐름

- 1a. 캡처 카메라나 Renderer 영역이 유효하지 않으면 시스템은 미리보기와 저장 버튼 대신 원인을 안내한다.
- 1b. 씬 또는 캡처 설정이 변경되어 미리보기가 오래된 상태가 되면 시스템은 다시 렌더링한 뒤 현재 분할선을 적용한다.
- 2a. 분할선이 없으면 시스템은 전체 캡처를 PNG 한 장으로 저장한다.
- 2b. 분할선을 추가할 때 시스템은 현재 가장 큰 구간의 가운데에 새 분할선을 배치한다.
- 4a. 분할선을 이동할 때 인접 분할선이나 이미지 끝과 겹치려 하면 시스템은 모든 구간이 최소 1픽셀을 유지하도록 이동 범위를 제한한다.
- 5a. 사용자가 폴더 선택 대화상자를 취소하면 시스템은 씬과 파일을 변경하지 않고 종료한다.
- 6a. 사용자가 렌더링 진행 창에서 취소하면 시스템은 불완전한 PNG를 저장하지 않고 임시 리소스를 정리한다.
- 7a. 같은 이름의 파일이 이미 있으면 시스템은 기본 파일명에 일련번호를 추가해 기존 파일을 덮어쓰지 않는다.
- 7b. 인코딩 또는 저장 중 오류가 발생하면 시스템은 이번 실행에서 생성한 결과 파일을 정리하고 오류를 Console에 기록한다.

## 인수 조건

- [x] 캡처 창에 실제 스테이지 내용과 같은 비율의 이미지 미리보기가 표시된다.
- [x] 분할선을 추가하면 결과 구간과 파일 수가 하나 늘어난다.
- [x] 분할선을 드래그하거나 삭제해 각 구간의 크기와 개수를 변경할 수 있다.
- [x] 분할선이 없으면 전체 캡처와 같은 PNG 한 장이 생성된다.
- [x] 여러 분할선이 있으면 전체 세로 길이가 누락이나 중복 없이 위에서 아래 순서의 PNG들로 나뉜다.
- [x] 분할 이미지의 너비는 모두 전체 캡처 너비와 동일하다.
- [x] 각 구간은 최소 1픽셀 높이를 유지하고 분할선끼리 교차하지 않는다.
- [x] 파일명은 `part-01-of-03`처럼 위에서 아래 순서를 식별할 수 있다.
- [x] 사용자가 선택한 폴더에 모든 결과 파일이 저장된다.
- [x] 기존 씬 오브젝트, 카메라, Collider와 Transform의 저장된 값이 변경되지 않는다.

## 구현 메모

- `Assets/Editor/StageCaptureWindow.cs`에서 기존 캡처 렌더링 결과를 구간별 PNG로 인코딩한다.
- 미리보기와 최종 캡처는 같은 임시 카메라 및 타일 렌더링 경로를 사용하며, 미리보기는 최대 `512 × 4096` 범위로 축소해 창에 표시한다.
- 분할선 위치는 전체 높이 대비 `0~1` 비율로 보관하고, 저장 시 정렬된 픽셀 구간으로 변환한다. 각 구간은 최소 1픽셀을 유지한다.
- `Add Divider`는 현재 가장 높은 구간의 가운데에 새 선을 추가하며, 사용자는 가로선을 드래그하거나 삭제하고 `Even Spacing`으로 균등 배치할 수 있다.
- 전체 RGB24 버퍼의 픽셀 행을 직접 복사하므로 구간 경계에서 재렌더링 오차나 중복이 생기지 않는다.
- 저장 전 같은 파일명이 있는지 확인하며, 충돌 시 기본 이름에 `-2`, `-3` 일련번호를 붙인다.
- 현재 Stage 1을 너비 512px·타일 높이 384px·2x MSAA로 캡처해 `N=1`의 `512 × 1793` 한 장과 `N=3`의 `512 × 598`, `512 × 598`, `512 × 597` 세 장을 생성했다. 세 분할 이미지의 모든 픽셀을 한 장 이미지와 대조해 위→아래 순서, 전체 높이, 경계 픽셀이 정확히 일치하는 것을 확인했다.
- Unity 6000.3.1f1 에디터 어셈블리 컴파일을 통과했다.
- Unity 6000.4.5f1 임시 프로젝트에서 에디터 어셈블리 컴파일을 통과했다.
- 현재 Stage 1을 `512 × 1640`으로 렌더링하고 23%·71% 위치에서 `377`, `787`, `476`픽셀 높이의 PNG 세 장으로 나눴다. 축소 미리보기가 단색이 아닌 실제 스테이지 이미지를 포함하고, 세 PNG의 모든 픽셀이 별도로 저장한 전체 PNG의 대응 행과 정확히 일치하는 것을 자동 검증했다.

# UC-007-01: 플레이테스트 이동 및 이벤트 로그 기록

- 상태: Implemented
- 마지막 갱신일: 2026-06-27

## 목적

개발자가 직접 플레이테스트한 뒤 난이도 조절에 참고할 수 있도록 Player의 이동 궤적과 핵심 이벤트를 로그 파일로 기록한다.

## 액터

- 개발자
- 맵 제작자
- 테스터

## 사전 조건

- Unity Editor에서 플레이 가능한 씬이 열려 있어야 한다.
- 씬에 `PlayerController`가 포함되어 있어야 한다.

## 트리거

- 사용자가 Play Mode에서 플레이테스트를 시작한다.

## 기본 흐름

1. 시스템은 Play Mode에서 Player를 찾는다.
2. 시스템은 플레이테스트 세션 로그 파일을 생성한다.
3. 시스템은 일정 간격으로 Player 위치를 이동 궤적 샘플로 기록한다.
4. 시스템은 점프 실행 시점의 위치, 각도, 파워, 점프 벡터를 이벤트로 기록한다.
5. 시스템은 실제 점프 후 Player가 다시 지면에 착륙하면 착륙 위치를 이벤트로 기록한다.
6. 시스템은 Player가 지정된 낙하 기준 아래로 내려가면 낙하 이벤트를 기록한다.
7. 시스템은 Play Mode 종료 또는 애플리케이션 종료 시 로그 파일을 닫는다.

## 대안 및 예외 흐름

- 1a. Player를 찾지 못하면 시스템은 로그 파일을 생성하지 않는다.
- 2a. 로그 폴더나 파일을 생성하지 못하면 시스템은 경고를 남기고 플레이를 계속한다.
- 5a. Player가 점프 실행 없이 발판에서 떨어졌다가 지면에 닿으면 시스템은 착륙 이벤트를 기록하지 않는다.
- 6a. 낙하 이벤트가 이미 기록된 뒤 Player가 계속 아래로 내려가면 같은 낙하를 중복 기록하지 않는다.
- 7a. 디버그 모드에서 `R` 또는 `T` 키로 점프 위치 히스토리를 이동하면 시스템은 이동 전후 샘플을 하나의 이동 궤적으로 연결하지 않는다.

## 인수 조건

- [ ] 플레이테스트 중 Player 이동 궤적 샘플이 파일에 기록된다.
- [ ] 점프 실행 시점이 이벤트 로그로 기록된다.
- [ ] 실제 점프 후 착륙 지점이 이벤트 로그로 기록된다.
- [ ] 낙하 지점이 이벤트 로그로 기록된다.
- [ ] 디버그 모드에서 `R` 또는 `T` 키로 이동한 구간은 이동 궤적 샘플 선으로 기록되지 않는다.
- [ ] 로그 기록 실패가 플레이 입력이나 물리 동작을 막지 않는다.

## 구현 메모

- `PlaytestLoggerBootstrap`이 Unity Editor Play Mode에서 `PlayerController`에 `PlaytestLogger`를 자동 추가한다.
- `PlaytestLogger`는 프로젝트 루트의 `PlaytestLogs/` 아래에 JSON Lines 로그 파일을 생성한다.
- 이동 샘플은 일정 간격으로 기록하되, 위치가 거의 변하지 않으면 새 샘플을 남기지 않아 정지 체류 시간이 로그를 부풀리지 않는다.
- `PlayerController`는 실제 점프 실행 시 `JumpExecuted` 이벤트를 발생시키고, `PlaytestLogger`가 이를 점프 이벤트로 기록한다.
- `PlayerController`는 실제 점프 후 지면에 착륙할 때 `Landed` 이벤트를 발생시키고, `PlaytestLogger`가 이를 착륙 이벤트로 기록한다.
- 낙하 이벤트는 `Tools/Jump Timing/Playtest Logs` 창의 `Fall Y Threshold` 설정 아래로 내려갈 때 기록된다.
- 착륙 이벤트는 점프 실행 없이 발판에서 떨어진 뒤 지면에 닿는 경우에는 기록하지 않는다.
- 디버그 모드에서 `R` 또는 `T` 키로 점프 위치 히스토리를 이동하면 `path_break` 레코드를 기록하고 다음 샘플과 이전 샘플이 하나의 궤적으로 연결되지 않게 한다.
- Unity Roslyn 응답 파일 기반으로 런타임 스크립트 컴파일을 확인했다.

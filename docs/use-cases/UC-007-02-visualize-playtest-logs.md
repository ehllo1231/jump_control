# UC-007-02: 플레이테스트 로그 Scene View 시각화

- 상태: Implemented
- 마지막 갱신일: 2026-06-27

## 목적

개발자가 기록된 플레이테스트 로그를 Unity Scene View에서 직관적으로 확인하여 어려운 구간을 찾는다.

## 액터

- 개발자
- 맵 제작자
- 테스터

## 사전 조건

- Unity Editor에서 프로젝트가 열려 있어야 한다.
- 플레이테스트 로그 파일이 하나 이상 존재해야 한다.

## 트리거

- 사용자가 플레이테스트 로그 창에서 로그 파일을 선택하고 Scene View 표시를 켠다.

## 기본 흐름

1. 시스템은 저장된 플레이테스트 로그 목록을 표시한다.
2. 시스템은 가장 최근 로그 파일을 기본 선택한다.
3. 사용자는 필요하면 확인할 로그 파일을 선택한다.
4. 시스템은 선택한 로그 파일에서 이동 샘플, 점프 이벤트, 착륙 이벤트, 낙하 이벤트를 읽는다.
5. 시스템은 Scene View에 이동 궤적을 선으로 표시한다.
6. 시스템은 점프 지점, 착륙 지점, 낙하 지점을 구분되는 마커로 표시한다.

## 대안 및 예외 흐름

- 1a. 로그 파일이 없으면 시스템은 로그가 없음을 안내한다.
- 4a. 선택한 로그 파일을 읽지 못하면 시스템은 오류를 표시하고 기존 표시를 유지하지 않는다.
- 5a. Scene View 표시가 꺼져 있으면 시스템은 로그를 읽어도 오버레이를 그리지 않는다.

## 인수 조건

- [ ] Editor 창에서 기록된 로그 목록을 확인할 수 있다.
- [ ] Play Mode 종료 후 가장 최근 로그가 자동으로 목록에 반영되고 선택된다.
- [ ] 선택한 로그의 이동 궤적이 Scene View에 표시된다.
- [ ] 로그에 기록된 궤적 끊김 지점에서는 Scene View 이동 궤적 선이 이어지지 않는다.
- [ ] 점프 지점, 착륙 지점, 낙하 지점이 서로 다른 색상/마커로 표시된다.

## 구현 메모

- `Tools/Jump Timing/Playtest Logs` Editor 창에서 로그 목록, 자동 기록 설정, 낙하 기준 Y, 요약 정보를 확인할 수 있다.
- Play Mode에서 Edit Mode로 돌아오면 로그 목록을 자동 갱신하고 가장 최근 로그를 선택한다.
- 선택한 로그는 Scene View 오버레이로 표시되며 이동 궤적, 점프 지점, 착륙 지점, 낙하 지점을 구분해서 그린다.
- 로그에 `path_break` 레코드가 있으면 해당 지점의 이전 샘플과 다음 샘플 사이에는 이동 궤적 선을 그리지 않는다.
- 이동 궤적은 겹침 정도와 관계없이 동일한 색상과 두께로 표시한다.
- Unity Roslyn 응답 파일 기반으로 Editor 스크립트 컴파일을 확인했다.
- Scene View에서 실제 로그를 선택해 착륙 마커와 궤적 끊김을 표시하는 수동 검증은 수행하지 않았으므로 상태는 `Verified`가 아닌 `Implemented`로 유지한다.

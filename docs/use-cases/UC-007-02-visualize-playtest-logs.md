# UC-007-02: 플레이테스트 로그 Scene View 시각화

- 상태: Implemented
- 마지막 갱신일: 2026-06-27

## 목적

개발자가 기록된 플레이테스트 로그를 Unity Scene View에서 직관적으로 확인하여 어려운 구간을 찾는다.

## 액터

- 개발자
- 맵 제작자
- 테스터

## 사전 조건

- Unity Editor에서 프로젝트가 열려 있어야 한다.
- 플레이테스트 로그 파일이 하나 이상 존재해야 한다.

## 트리거

- 사용자가 플레이테스트 로그 창에서 로그 파일을 선택하고 Scene View 표시를 켠다.

## 기본 흐름

1. 시스템은 저장된 플레이테스트 로그 목록을 표시한다.
2. 사용자는 확인할 로그 파일을 선택한다.
3. 시스템은 선택한 로그 파일에서 이동 샘플, 점프 이벤트, 낙하 이벤트를 읽는다.
4. 시스템은 Scene View에 이동 궤적을 선으로 표시한다.
5. 시스템은 같은 구간에 궤적이 많이 누적된 부분을 더 강하게 표시한다.
6. 시스템은 점프 지점과 낙하 지점을 구분되는 마커로 표시한다.

## 대안 및 예외 흐름

- 1a. 로그 파일이 없으면 시스템은 로그가 없음을 안내한다.
- 3a. 선택한 로그 파일을 읽지 못하면 시스템은 오류를 표시하고 기존 표시를 유지하지 않는다.
- 4a. Scene View 표시가 꺼져 있으면 시스템은 로그를 읽어도 오버레이를 그리지 않는다.

## 인수 조건

- [ ] Editor 창에서 기록된 로그 목록을 확인할 수 있다.
- [ ] 선택한 로그의 이동 궤적이 Scene View에 표시된다.
- [ ] 궤적이 많이 겹치는 구간은 시각적으로 더 강조된다.
- [ ] 점프 지점과 낙하 지점이 서로 다른 색상/마커로 표시된다.

## 구현 메모

- `Tools/Jump Timing/Playtest Logs` Editor 창에서 로그 목록, 자동 기록 설정, 낙하 기준 Y, 요약 정보를 확인할 수 있다.
- 선택한 로그는 Scene View 오버레이로 표시되며 이동 궤적, 점프 지점, 낙하 지점을 구분해서 그린다.
- 이동 궤적 밀도는 샘플 선분의 중간점이 속한 그리드 셀별 누적 수로 계산하고, 누적이 많은 구간은 더 굵고 밝은 선으로 표시한다.
- Unity Roslyn 응답 파일 기반으로 Editor 스크립트 컴파일을 확인했다.
- Scene View에서 실제 로그를 선택해 표시하는 수동 검증은 수행하지 않았으므로 상태는 `Verified`가 아닌 `Implemented`로 유지한다.

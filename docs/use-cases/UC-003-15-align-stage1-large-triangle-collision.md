# UC-003-15: Stage1 큰 삼각형 시각 경계와 충돌 정렬

- 상태: Superseded
- 마지막 갱신일: 2026-07-26

## 목적

플레이어가 Stage1의 가장 큰 삼각형에서 화면에 보이는 외곽선과 일치하는 충돌 판정을 경험한다.

> 해당 삼각형은 Stage1 전체 재디자인을 위해 제거되었다. 현재 상태는 [UC-003-17](./UC-003-17-reset-stage1-for-redesign.md)로 대체한다.

## 액터

- 플레이어
- 맵 제작자
- 개발자

## 사전 조건

- `Assets/Scenes/MVPJumpScene.unity`에 가장 큰 회색 삼각형 외형이 표시되어 있다.
- `Stage1/Collision` 아래에 해당 삼각형의 충돌 전용 `PolygonCollider2D`가 존재한다.

## 트리거

- 플레이어가 가장 큰 삼각형의 윗변, 빗변 또는 모서리에 접근한다.

## 기본 흐름

1. 시스템은 화면에 보이는 큰 삼각형의 세 꼭지점 월드 좌표를 기준으로 충돌 경계를 정한다.
2. 시스템은 `Stage1/Collision`의 충돌 전용 `PolygonCollider2D`가 그 경계를 따르게 한다.
3. 시스템은 화면에 보이는 삼각형 쪽에 남아 있던 중복 `PolygonCollider2D`를 비활성화한다.
4. 플레이어는 보이는 윗변과 빗변에서만 해당 삼각형과 충돌한다.

## 대안 및 예외 흐름

- 1a. 시각 삼각형과 충돌 전용 삼각형이 서로 다른 Transform을 사용하면 시스템은 시각 꼭지점을 충돌 오브젝트의 로컬 좌표로 변환해 저장한다.
- 3a. 시각 삼각형을 생성하는 `Platform2D`가 유지되어야 하면 컴포넌트는 유지하되 중복 Collider만 비활성 상태로 저장한다.

## 인수 조건

- [x] 큰 삼각형의 충돌 전용 `PolygonCollider2D` 월드 꼭지점이 화면에 보이는 삼각형의 세 꼭지점과 일치한다.
- [x] 큰 삼각형에 물리 충돌을 제공하는 `PolygonCollider2D`가 하나만 존재한다.
- [x] 보이는 빗변 아래나 오른쪽 끝 바깥에서 보이지 않는 물리 충돌이 발생하지 않는다.
- [x] 다른 Stage1 Collider와 Transform은 변경되지 않는다.
- [x] 씬 저장과 Unity 재컴파일 뒤에도 정렬과 단일 물리 Collider 상태가 유지된다.

## 구현 메모

- 진단 당시 루트 `Platform (1)`과 `Stage1/Collision/Platform (1)`에 서로 다른 활성 `PolygonCollider2D`가 겹쳐 있었다.
- 충돌 전용 삼각형은 보이는 빗변보다 약 `0.27~0.35` 월드 단위 아래에 있고 오른쪽 끝이 약 `0.48` 월드 단위 더 돌출되어 있었다.
- 보이는 삼각형의 월드 꼭지점을 `Stage1/Collision/Platform (1)` 로컬 좌표 `(-8.662489, 3.3216782)`, `(-8.662489, -6.2416763)`, `(9.722488, 3.3216782)`로 변환해 충돌 경로와 `Platform2D` 직렬화 값에 함께 저장했다.
- 보이는 루트 `Platform (1)`의 중복 Collider는 `Trigger`로 전환했다. 플레이어 물리 충돌, `GroundChecker`의 지면 판정, 점프 도달 장애물 판정은 Trigger를 제외한다.
- Unity 6000.3.1f1에서 씬을 저장하고 임시 적용 스크립트 제거 후 Editor 어셈블리 재컴파일을 완료했다. 컴파일 오류는 없었다.
- 직렬화 좌표 검증에서 시각 삼각형과 충돌 전용 삼각형의 월드 꼭지점 최대 오차는 약 `0.0000038` 월드 단위였다.
- 작업 직전 자동 백업 씬과 비교해 변경이 해당 삼각형의 꼭지점·크기 8줄과 중복 Collider의 Trigger 1줄에만 한정됨을 확인했다.
- 2026-07-26 `UC-003-17` 초기화에서 해당 삼각형과 가이드를 제거했으며, 기존 결과는 기준점 커밋과 백업 씬에서 복구할 수 있다.

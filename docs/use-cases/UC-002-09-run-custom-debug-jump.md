# UC-002-09: 디버그 커스텀 점프 실행

- 상태: Implemented
- 마지막 갱신일: 2026-06-24

## 목적

개발자 또는 테스터가 Play Mode에서 디버그 모드를 켠 상태로 원하는 점프 각도와 게이지 퍼센트를 입력하고, 일반 점프와 같은 시각 표시를 확인한 뒤 설정한 점프로 주인공을 이동시킨다.

## 액터

- 개발자
- 테스터

## 사전 조건

- Play Mode에서 주인공을 조작할 수 있어야 한다.
- 설정에서 디버그 모드가 활성화되어 있어야 한다.
- 주인공이 지면에 있어야 한다.

## 트리거

- 개발자 또는 테스터가 주인공 옆의 `Custom Jump` 버튼을 누른다.

## 기본 흐름

1. 시스템은 디버그 모드가 활성화된 Play Mode에서 주인공 옆에 `Custom Jump` 버튼을 표시한다.
2. 사용자가 `Custom Jump` 버튼을 누른다.
3. 시스템은 점프 각도와 게이지 퍼센트를 입력할 수 있는 창을 표시한다.
4. 사용자가 점프 각도와 게이지 퍼센트를 입력한다.
5. 시스템은 입력된 값에 맞춰 일반 점프처럼 방향 화살표와 파워 게이지를 표시한다.
6. 사용자가 스페이스바를 누른다.
7. 시스템은 입력된 각도와 게이지 퍼센트를 현재 점프 설정에 적용해 점프 힘을 계산하고 주인공을 점프시킨다.

## 대안 및 예외 흐름

- 1a. 디버그 모드가 비활성화되어 있으면 시스템은 `Custom Jump` 버튼과 입력 창을 표시하지 않는다.
- 3a. 사용자가 입력 창에서 취소를 선택하면 시스템은 커스텀 점프 준비를 종료하고 일반 점프 입력을 다시 받는다.
- 4a. 게이지 퍼센트가 `0~100` 범위를 벗어나면 시스템은 `0~100` 범위로 제한한다.
- 6a. 주인공이 공중에 있으면 시스템은 커스텀 점프를 실행하지 않고 착지를 기다린다.
- 6b. 디버그 모드 중에도 사용자가 일반 점프 입력을 진행하면 시스템은 기존 일반 점프 흐름을 유지한다.

## 인수 조건

- [ ] 설정에서 체크박스로 디버그 모드를 켜고 끌 수 있다.
- [ ] 디버그 모드가 켜진 Play Mode에서만 주인공 옆에 `Custom Jump` 버튼이 표시된다.
- [ ] `Custom Jump` 버튼을 누르면 각도와 게이지 퍼센트 입력 창이 표시된다.
- [ ] 입력된 각도와 게이지 퍼센트가 일반 점프의 방향 화살표와 파워 게이지로 표시된다.
- [ ] 입력 창이 열린 상태에서 스페이스바를 누르면 입력값으로 계산한 점프가 실행된다.
- [ ] 입력 창에서 취소하면 커스텀 점프 준비가 종료되고 일반 점프를 다시 사용할 수 있다.
- [ ] 디버그 모드가 켜져 있어도 기존 일반 점프 흐름을 사용할 수 있다.

## 구현 메모

- `JumpTuningConfig`에 `debugModeEnabled` 체크박스를 추가하고 `Jump Tuning` 창의 `Debug Mode` 섹션에서 편집할 수 있게 했다.
- `PlayerController`는 Play Mode에서 디버그 모드가 켜져 있을 때 주인공 옆에 `Custom Jump` 버튼을 표시한다.
- `Custom Jump` 버튼은 주인공이 지면에 있고 일반 점프 준비가 진행 중이지 않은 `Idle` 상태에서 커스텀 입력 창을 연다.
- 커스텀 입력 창은 각도와 게이지 퍼센트 문자열을 받고, 입력값을 `JumpAngleAim.ShowAngle`과 `JumpPowerGauge.ShowLockedValue`로 즉시 표시한다.
- 커스텀 입력 창이 열린 동안 스페이스바를 누르면 입력 각도와 게이지 퍼센트로 점프 방향과 힘을 계산해 `PlayerJumpMotor`의 기존 점프 실행 경로를 사용한다.
- 커스텀 입력 창의 `Cancel` 버튼은 방향 화살표와 게이지를 숨기고 일반 점프 입력을 다시 받을 수 있게 한다.
- 커스텀 입력 창이 열려 있지 않으면 디버그 모드에서도 기존 일반 점프 상태 흐름을 그대로 사용한다.
- 게이지 퍼센트는 실행 및 표시 시 `0~100` 범위로 제한한다.
- Unity batchmode 컴파일은 같은 프로젝트가 이미 Unity에 열려 있어 실행하지 못했다.
- Unity 6000.3.1f1의 Bee rsp를 기반으로 임시 Roslyn 컴파일을 실행해 런타임 및 Editor 스크립트 컴파일을 확인했다.

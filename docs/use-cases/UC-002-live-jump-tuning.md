# UC-002: 실시간 점프 튜닝

- 상태: Implemented
- 마지막 갱신일: 2026-06-21

## 목적

개발자 또는 테스터가 Unity의 전용 Tools 창 한 곳에서 주인공 사각형 크기, 점프 각도, 방향 이동 속도, 게이지 차징 속도, 최소·최대 점프 세기와 게이지 반응 곡선을 변경하고 즉시 결과를 확인한다.

## 액터

- 개발자
- 테스터

## 사전 조건

- Unity Editor에서 MVP 점프 씬과 Player 오브젝트를 사용할 수 있어야 한다.
- Player 오브젝트에 `PlayerController`가 연결되어 있어야 한다.

## 트리거

- 개발자 또는 테스터가 `Tools > Jump Timing > Jump Tuning`을 연다.

## 기본 흐름

1. 개발자 또는 테스터가 `Tools > Jump Timing > Jump Tuning` 창을 연다.
2. 시스템은 선택된 Player, 현재 씬의 Player, Player 프리팹 순서로 튜닝 대상을 자동 선택한다.
3. 시스템은 주인공 사각형 크기, 방향 최소·최대 각도, 방향 왕복 속도, 시작 위치, 게이지 차징 시간, 최소·최대 점프 세기와 반응 곡선을 한 화면에 표시한다.
4. 개발자 또는 테스터가 Tools 창에서 주인공 사각형 크기를 변경한다.
5. 시스템은 주인공 스프라이트와 충돌체 크기를 함께 변경하고 지면 판정 범위를 새 충돌체 크기에 맞춘다.
6. 개발자 또는 테스터가 Tools 창에서 방향 설정을 변경한다.
7. 시스템은 변경된 방향 설정을 진행 중이거나 다음 방향 조준에 즉시 적용한다.
8. 개발자 또는 테스터가 Tools 창에서 차징 시간, 최소·최대 점프 세기 또는 반응 곡선을 변경한다.
9. 시스템은 변경된 게이지 설정을 진행 중이거나 다음 점프에 즉시 적용한다.

## 대안 및 예외 흐름

- 2a. 선택된 오브젝트에 PlayerController가 있으면 시스템은 해당 Player를 대상으로 사용한다.
- 2b. 선택된 Player가 없으면 시스템은 현재 씬의 Player를 대상으로 사용한다.
- 2c. 현재 씬에도 Player가 없으면 시스템은 `Assets/Prefabs/Player.prefab`을 대상으로 사용한다.
- 2d. 유효한 대상이 없으면 시스템은 안내 메시지와 대상 찾기 버튼을 표시한다.
- 4a. 주인공 사각형 크기가 `0.1`보다 작으면 시스템은 `0.1`로 제한한다.
- 6a. 최소 각도가 최대 각도보다 크면 시스템은 계산 시 두 값을 올바른 순서로 사용한다.
- 8a. 차징 시간이 `0.05초`보다 작으면 시스템은 `0.05초`로 제한한다.
- 8b. 최소 점프 세기가 최대 점프 세기보다 크면 시스템은 계산 시 두 값을 올바른 순서로 사용한다.
- 8c. 게이지 반응 곡선이 비어 있으면 시스템은 기본 선형 곡선 `0→0`, `1→1`을 사용한다.
- 8d. 반응 곡선이 `0~1` 범위를 벗어난 값을 반환하면 시스템은 결과를 `0~1`로 제한한다.

- [ ] 주인공 크기, 방향과 게이지 관련 튜닝 값을 Tools 창 한 화면에서 변경할 수 있다.
- [ ] 선택된 Player, 씬 Player 또는 Player 프리팹 중 편집 대상을 확인하고 바꿀 수 있다.
- [ ] 주인공 사각형 크기를 Tools 창에서 변경하면 스프라이트와 BoxCollider2D 크기가 함께 변경된다.
- [ ] 주인공 크기를 변경해도 지면 판정 영역이 새 충돌체 하단과 폭을 따른다.
- [ ] 최소·최대 방향 각도와 방향 왕복 속도를 Tools 창에서 변경할 수 있다.
- [ ] 게이지 최소→최대 차징 시간을 Tools 창에서 변경할 수 있다.
- [ ] 최소·최대 점프 세기를 Tools 창에서 각각 변경할 수 있다.
- [ ] AnimationCurve로 최소·최대 사이의 정규화 게이지 반응을 Tools 창에서 변경할 수 있다.
- [ ] Play Mode 중 변경한 값이 현재 진행 중이거나 다음 점프부터 코드 재컴파일 없이 반영된다.
- [ ] 기본 설정은 주인공 크기 `0.72`, 방향 `-62°~62°`, 방향 속도 `145°/초`, 차징 시간 `1.15초`, 점프 세기 `7~16`을 유지한다.

## 구현 메모

- 직렬화 가능한 `JumpTuningConfig`를 추가하고 PlayerController가 방향 및 게이지 컴포넌트와 공유하도록 구성했다.
- `Tools > Jump Timing > Jump Tuning`에서 열리는 `JumpTuningWindow`를 추가했다.
- Tools 창은 선택된 Player, 현재 씬 Player, Player 프리팹 순서로 대상을 자동 탐색하며 수동 전환 버튼도 제공한다.
- 방향과 게이지 설정을 구분해 한 화면에 모두 표시하고, 씬 대상은 변경된 씬을 Dirty 상태로 표시하며 프리팹 대상은 프리팹 에셋에 저장한다.
- Tools 창의 `Player Body > Player Square Size`에서 주인공 크기를 조정하도록 추가했다.
- 크기 변경 시 `PlayerVisual`의 스프라이트 스케일과 Player의 `BoxCollider2D.size`를 동일한 값으로 갱신한다.
- `GroundChecker`는 고정된 GroundCheck 위치 대신 변경된 콜라이더의 실제 하단과 폭을 기준으로 지면을 검사한다.
- 주인공 사각형 크기의 기본값은 `0.72`, 최솟값은 `0.1`이다.
- `JumpAngleAim`은 조준 중 매 프레임 설정된 최소·최대 각도와 방향 속도를 읽으므로 Play Mode 변경값이 즉시 반영된다.
- `JumpPowerGauge`는 차징 중 매 프레임 설정된 차징 시간, 최소·최대 점프 세기와 반응 곡선을 읽는다.
- `Minimum Jump Power`와 `Maximum Jump Power`를 추가했으며 기본값은 각각 `7`, `16`이다.
- 점프 세기 반응 곡선은 X축 정규화 게이지 `0~1`, Y축 최소·최대 사이의 보간 비율 `0~1`을 의미한다.
- 잘못된 각도 및 점프 세기 순서, 너무 짧은 차징 시간, 빈 곡선과 범위를 벗어난 곡선 결과에 안전한 제한값을 적용했다.
- Unity 내장 Roslyn 컴파일러로 전체 런타임 스크립트와 `JumpTuningWindow` Editor 스크립트 컴파일을 확인했다. 오류는 없고 런타임의 기존 직렬화 필드 관련 경고 2건만 발생했다.
- Play Mode에서 Tools 창 값을 직접 변경하는 수동 검증은 수행하지 않았으므로 상태는 `Verified`가 아닌 `Implemented`로 유지한다.

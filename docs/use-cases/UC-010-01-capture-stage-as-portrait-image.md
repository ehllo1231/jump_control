# UC-010-01: 스테이지 전체를 세로 고화질 이미지로 저장

- 상태: Verified
- 마지막 갱신일: 2026-07-17

## 목적

맵 제작자가 현재 열린 스테이지 전체를 분할하지 않은 한 장의 세로형 고해상도 PNG 이미지로 저장한다.

## 액터

- 맵 제작자
- 개발자

## 사전 조건

- Unity Editor에서 저장할 스테이지 씬이 열려 있어야 한다.
- 활성 씬에 Orthographic Camera와 활성 Renderer가 하나 이상 있어야 한다.

## 트리거

- 사용자가 `Tools > Jump Timing > Stage Capture`를 열고 `Vertical Sections`를 1로 설정한 뒤 PNG 저장 버튼을 누른다.

## 기본 흐름

1. 시스템은 활성 씬과 캡처에 사용할 Orthographic Camera를 확인한다.
2. 시스템은 카메라에 표시되는 활성 Renderer들의 월드 영역을 계산하고, 스테이지의 좌우 경계 구조물이 Content Root보다 돌출되어 있어도 전체 폭을 포함한다.
3. 시스템은 지정한 이미지 너비와 스테이지 월드 영역의 비율을 사용해 이미지 높이를 자동 계산한다.
4. 사용자는 PNG를 저장할 폴더를 선택한다.
5. 시스템은 원본 카메라 설정을 복사한 임시 카메라로 스테이지를 여러 세로 타일로 렌더링한다.
6. 시스템은 렌더링 타일을 한 장의 이미지로 결합해 PNG 파일로 저장한다.
7. 시스템은 자동 생성된 파일 이름, 저장 폴더와 해상도를 안내한다.

## 대안 및 예외 흐름

- 1a. 활성 씬이 없거나 캡처 카메라가 없으면 시스템은 저장을 시작하지 않고 원인을 안내한다.
- 1b. 캡처 카메라가 Perspective Camera이면 시스템은 저장을 시작하지 않고 Orthographic Camera가 필요하다고 안내한다.
- 2a. Content Root를 지정하면 시스템은 해당 루트와 자식 Renderer를 기준 영역으로 사용하고, 같은 스테이지 안에서 기준 영역의 세로 범위와 겹치는 좌우 경계 Renderer를 함께 포함한다.
- 2b. 카메라의 Culling Mask에 포함되는 활성 Renderer가 없으면 시스템은 저장을 시작하지 않고 원인을 안내한다.
- 3a. 계산된 이미지 크기가 그래픽 장치의 최대 텍스처 크기를 넘으면 시스템은 권장 이미지 너비를 안내하고 저장하지 않는다.
- 4a. 사용자가 폴더 선택 대화상자를 취소하면 시스템은 씬과 파일을 변경하지 않고 종료한다.
- 5a. 사용자가 진행 창에서 취소하면 시스템은 불완전한 PNG를 저장하지 않고 임시 리소스를 정리한다.
- 6a. 렌더링 또는 파일 저장 중 오류가 발생하면 시스템은 임시 리소스를 정리하고 오류를 Console에 기록한다.

## 인수 조건

- [x] `Tools > Jump Timing > Stage Capture`에서 캡처 창을 열 수 있다.
- [x] 현재 Stage 1의 전체 Renderer 영역과 예상 PNG 해상도를 확인할 수 있다.
- [x] 출력 너비를 지정하면 스테이지 비율에 맞는 세로 이미지 높이가 자동 계산된다.
- [x] 세로 분할 개수가 1이면 선택한 폴더에 스테이지 전체가 잘리지 않은 하나의 PNG 파일이 생성된다.
- [x] Stage 1의 가장 오른쪽 벽이 Content Root의 오른쪽 경계보다 돌출되어 있어도 벽 전체와 여백이 PNG 안에 포함된다.
- [x] 고해상도 이미지도 타일 단위로 렌더링되어 단일 대형 RenderTexture 사용을 피한다.
- [x] 캡처 과정에서 원본 카메라와 씬 오브젝트의 저장된 설정이 바뀌지 않는다.

## 구현 메모

- `Assets/Editor/StageCaptureWindow.cs`가 `Tools > Jump Timing > Stage Capture` 에디터 창을 제공한다.
- `Vertical Sections`가 1이면 사용자가 선택한 폴더에 기존과 동일한 전체 해상도의 PNG 한 장을 자동 파일명으로 저장한다.
- Stage 1에서는 현재 계층 아래에 중첩된 `Demon Castle Interior`도 재귀적으로 찾아 Content Root로 자동 선택하고, 일반 씬에서는 자식 Renderer가 가장 많은 루트를 기본 후보로 사용한다.
- 캡처 카메라의 Culling Mask와 선택적 Content Root를 기준으로 활성 Renderer의 카메라 공간 영역을 계산한다. Content Root는 기본 영역을 정하고, 해당 영역의 세로 범위와 겹치는 스테이지 경계 Renderer를 영역 계산에 보강해 안전용 바닥 같은 먼 오브젝트는 제외하면서 좌우 벽 잘림을 막는다.
- 경계 보강은 Content Root와 같은 최상위 스테이지 계층에서 수평으로 맞닿고 기준 영역보다 폭이 크지 않은 Renderer만 포함한다. 따라서 Stage 1 오른쪽 벽은 포함하지만 `x=-500~500` 범위의 대형 안전 바닥은 제외한다.
- 지정한 PNG 너비와 월드 영역 비율로 높이를 자동 계산하고, 장치 최대 텍스처 크기를 넘으면 권장 너비를 안내한다.
- 임시 카메라가 원본 카메라 설정을 복사하며, 긴 이미지는 여러 RenderTexture 타일로 렌더링한 뒤 하나의 `Texture2D`에 결합한다.
- MSAA 타일은 단일 샘플 RenderTexture로 resolve한 다음 PNG 버퍼로 읽는다.
- Unity 6000.3.1f1 에디터 어셈블리 컴파일을 통과했다.
- 원본 프로젝트와 분리된 Stage 1 복사본에서 너비 512px, 타일 높이 384px, 2x MSAA로 실제 캡처를 실행했다. `512 × 1823` RGB PNG가 생성됐고, 배경·Platform·Player를 포함한 전체 세로 스테이지와 타일 경계가 자연스럽게 이어지는 것을 직접 확인했다.
- 현재 Stage 1에서 배경의 오른쪽 끝 `x=21.660`보다 오른쪽 벽이 `x=23.772`까지 돌출된 회귀 조건을 확인했다. 수정 후 캡처 영역은 기본 여백을 포함해 `x=24.272`까지 확장됐으며, 너비 512px·타일 높이 384px·2x MSAA로 생성한 `512 × 1793` PNG에서 오른쪽 벽 전체와 바깥 여백이 보이는 것을 직접 확인했다.
- 현재 Stage 1에서 `Vertical Sections=1`로 `512 × 1793` PNG 한 장을 폴더 기반 저장 방식으로 생성하고 전체 해상도가 유지되는 것을 확인했다.

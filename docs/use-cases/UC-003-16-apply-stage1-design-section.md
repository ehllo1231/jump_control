# UC-003-16: Stage1 분할 디자인 파츠 적용

- 상태: Superseded
- 마지막 갱신일: 2026-07-26

## 목적

아트 디자이너가 Stage1 전체 캡처를 세로로 나눈 그레이박스를 기준으로 여러 디자인 파츠를 실제 충돌 구조와 독립된 시각 요소로 조립한다.

> 이 디자인 파츠와 적용 도구는 Stage1 전체 재디자인을 위해 제거되었다. 현재 상태는 [UC-003-17](./UC-003-17-reset-stage1-for-redesign.md)로 대체한다.

## 액터

- 아트 디자이너
- 맵 제작자
- 개발자

## 사전 조건

- `Assets/Scenes/MVPJumpScene.unity`에 `Stage1/Collision`과 `Stage1/ForegroundDecor/StageArt`가 존재한다.
- 첫 번째 구간 참고 이미지 `1-1그레이박스.png`와 디자인 이미지 `parts1.png`부터 `parts5.png`가 `Assets/Art/graybox_design/stage1/stage1-1_design`에 존재한다.

## 트리거

- 아트 디자이너가 Stage1 첫 번째 구간의 그레이박스를 실제 디자인 파츠로 채우려 한다.

## 기본 흐름

1. 시스템은 `1-1그레이박스.png`의 외벽, 내부 구조와 부유 발판 픽셀 경계를 첫 번째 구간의 월드 범위에 대응시킨다.
2. 시스템은 `parts1.png`부터 `parts5.png`를 투명 Sprite 에셋으로 가져온다.
3. 시스템은 `Stage1/ForegroundDecor/StageArt` 아래에 첫 번째 구간 전용 테스트 루트를 생성한다.
4. 시스템은 `parts1`을 전체 기반 아트로 배치하고, `parts2`와 `parts3`을 내부 구조 보강 아트로 정렬한다.
5. 시스템은 `parts4`와 `parts5`를 두 부유 발판의 윗면과 가로폭에 맞춰 배치한다.
6. 시스템은 모든 디자인을 플레이어보다 뒤에 표시하고, 기존 회색 `CollisionGuides`와 선택적으로 비교할 수 있게 한다.
7. 맵 제작자는 Scene View 또는 Play Mode에서 디자인과 실제 충돌 경계의 대응을 확인한다.

## 대안 및 예외 흐름

- 1a. 파츠의 캔버스 크기가 예상값과 다르면 시스템은 잘못된 배치를 저장하지 않고 오류를 보고한다.
- 3a. 같은 이름의 테스트 루트가 이미 있으면 중복 생성하지 않고 해당 루트의 디자인 오브젝트를 갱신한다.
- 6a. 디자인 검토가 끝나지 않은 구역은 `CollisionGuides`를 유지해 실제 충돌 구조를 계속 비교할 수 있다.
- 7a. 결과를 되돌릴 때는 첫 번째 구간 전용 테스트 루트만 제거하여 Collision과 다른 StageArt를 보존한다.

## 인수 조건

- [x] 새 디자인은 `Stage1/ForegroundDecor/StageArt` 아래에만 생성된다.
- [x] `Parts1`부터 `Parts5`까지 다섯 SpriteRenderer가 생성된다.
- [x] 디자인 오브젝트에는 Collider, Rigidbody2D와 `Platform2D`가 없다.
- [x] 기존 `Stage1/Collision`의 Transform과 Collider 직렬화 값은 변경되지 않는다.
- [x] 외벽, 바닥, 내부 구조와 두 부유 발판의 플레이 표면이 그레이박스 윤곽에 대응한다.
- [x] 디자인은 플레이어보다 뒤에 렌더링된다.
- [x] 같은 구간을 다시 적용해도 디자인 오브젝트가 중복되지 않는다.
- [x] 테스트 전용 루트를 제거하면 디자인만 롤백되고 Collision과 다른 StageArt는 보존된다.

## 구현 메모

- 기존 `structure1.png`와 `design1.png`를 사용한 단일 합성 이미지 배치는 다섯 파츠 조립 방식으로 교체한다.
- `1-1그레이박스.png`는 기존 `structure1.png`에서 위쪽 96px을 제외한 `2160 × 1515` 크롭과 픽셀이 정확히 일치한다.
- `Parts1`은 전체 기반 구조의 픽셀 경계 `(368, 0)~(2143, 1498)`에 배치하고 Order 5를 사용한다.
- `Parts2`와 `Parts3`은 각각 오른쪽 내부 구조 `(1219, 0)~(1687, 1213)`, 중앙 왼쪽 구조 `(1034, 51)~(1456, 826)`에 배치하고 Order 6을 사용한다.
- `Parts4`와 `Parts5`는 각각 부유 발판 `(1194, 178)~(1306, 204)`, `(1364, 250)~(1476, 277)`의 폭과 윗면에 균일 확대해 배치하고 Order 6을 사용한다.
- Unity 6000.3.1f1에서 스크립트 컴파일, 파츠 임포트, 적용, 재적용과 롤백을 통과했다. 재적용 후에도 다섯 Renderer만 존재하고 롤백 후에는 테스트 루트가 제거됐다.
- 적용 도구가 작업 전후 `Stage1/Collision` 전체 Transform과 Collider 직렬화 상태를 비교했으며 변경이 없음을 확인했다.
- 그래픽 모드 배치 실행으로 `2160 × 1515` 프리뷰를 생성해 외벽, 바닥, 내부 구조와 두 부유 발판 영역이 디자인으로 덮이는 것을 확인했다.
- 2026-07-26 `UC-003-17` 초기화에서 `DesignTest_Section_01_of_05`, 원본 파츠, 프리뷰와 재적용 도구를 제거했다. 기존 결과는 기준점 커밋과 백업 씬에서 복구할 수 있다.

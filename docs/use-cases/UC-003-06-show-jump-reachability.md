# UC-003-06: 점프 도달 후보 표시

- 상태: Implemented
- 마지막 갱신일: 2026-06-22

## 목적

맵 제작자가 Scene View에서 Player 현재 위치 기준으로 점프 도달 후보 궤적과 착지 가능한 Platform 후보를 확인한다.

## 액터

- 맵 제작자
- 개발자
- 테스터

## 사전 조건

- Unity Editor에서 맵 씬이 열려 있어야 한다.
- 씬에 `PlayerController`가 있어야 한다.
- 씬에 `Platform2D`가 있어야 한다.

## 트리거

- 사용자가 Map Builder의 `Show In Scene View` 토글 또는 `Tools > Jump Timing > Show Jump Reachability` 메뉴를 켠다.

## 기본 흐름

1. 시스템은 Player 현재 위치를 찾는다.
2. 시스템은 현재 `JumpTuningConfig`의 각도 범위와 점프 세기 범위를 읽는다.
3. 시스템은 Rigidbody2D mass, gravityScale과 `PlayerJumpMotor`의 impulse 배율을 읽는다.
4. 시스템은 Scene View에 점프 가능한 공간을 채워진 영역으로 표시한다.
5. 시스템은 Rigidbody2D gravityScale, mass, linearDamping과 `PlayerJumpMotor`의 impulse 배율을 실제 점프에 가깝게 반영한다.
6. 시스템은 장애물 Collider에 막힌 궤적 이후 구간을 도달 영역에서 제외한다.
7. 시스템은 벽 방향 충돌이 발생하면 현재 벽 반동 튜닝 값을 기준으로 반동 이후 궤적을 이어서 계산한다.
8. 시스템은 하강 중 Platform 윗면과 만나는 궤적을 찾는다.
9. 시스템은 Player 폭이 들어갈 수 있는 Platform 착지 구간과 후보 지점을 강조한다.

## 대안 및 예외 흐름

- 1a. PlayerController를 찾지 못하면 시스템은 점프 도달 후보 궤적을 표시하지 않는다.
- 6a. 궤적이 바닥, 천장, 비벽 방향 장애물 Collider와 먼저 충돌하면 시스템은 그 이후 공간을 표시하지 않는다.
- 7a. 벽 반동 탄성이 `0`이면 시스템은 기존처럼 벽 충돌 지점 이후 공간을 표시하지 않는다.
- 8a. 샘플 궤적이 Platform 윗면과 만나지 않으면 착지 후보를 강조하지 않는다.

## 인수 조건

- [ ] Scene View에서 Player 현재 위치 기준 점프 도달 가능 공간을 채워진 영역으로 확인할 수 있다.
- [ ] 현재 점프 튜닝의 각도 범위와 점프 세기 범위가 도달 후보 궤적에 반영된다.
- [ ] Rigidbody2D linearDamping이 있는 경우 도달 영역이 실제 Play Mode 점프보다 넓게 표시되지 않도록 감쇠를 반영한다.
- [ ] 장애물 Collider에 막힌 이후 구간은 도달 영역으로 칠해지지 않는다.
- [ ] 현재 벽 반동 탄성과 세로 속도 처리 방식이 도달 후보 궤적에 반영된다.
- [ ] 벽 방향 충돌 후 반동으로 이어지는 구간도 도달 영역으로 표시된다.
- [ ] 샘플 궤적이 하강 중 Platform 윗면과 만나는 경우 해당 Platform이 도달 후보로 강조된다.
- [ ] 회전된 Platform은 실제 월드 꼭지점 기준으로 수평 윗변이 있는 경우에만 착지 후보로 강조된다.
- [ ] Map Builder 창과 Tools 메뉴에서 표시를 켜고 끌 수 있다.
- [ ] Scene View 표시 계산과 렌더링은 캐시와 Mesh 기반 렌더링으로 과도한 렉을 피한다.

## 구현 메모

- `JumpReachabilityOverlay`가 Scene View에서 선 묶음 대신 점프 도달 가능 공간을 채워진 Mesh 영역으로 표시한다.
- 궤적 계산은 Player 현재 위치, `JumpTuningConfig`, `PlayerJumpMotor`, Rigidbody2D mass, gravityScale, linearDamping을 기준으로 한다.
- 미리보기 궤적은 닫힌 공식 대신 `Time.fixedDeltaTime` 이하 간격으로 중력과 linearDamping을 적분해 실제 Play Mode 점프보다 과하게 넓게 표시되는 문제를 줄였다.
- 각 샘플 궤적은 Player 크기의 BoxCast로 장애물 Collider를 판정하고, 벽 반동이 적용되지 않는 장애물 뒤쪽 구간은 도달 영역으로 칠하지 않는다.
- 벽 방향 충돌은 현재 벽 반동 튜닝 값을 기준으로 가로 속도를 되돌리고, 세로 속도 처리 방식에 따라 충돌 전 또는 현재 세로 속도를 유지해 궤적을 이어간다.
- 벽 반동 미리보기는 런타임과 같은 최소 이탈 속도와 벽 분리 거리를 반영해, 벽에 붙는 상황을 줄인 새 벽 반동 궤적에 가깝게 표시한다.
- 미리보기 궤적은 무한 반복 충돌을 피하기 위해 샘플 궤적당 벽 반동을 최대 4회까지 반영한다.
- BoxCast 크기 보정값을 줄여 Player Collider 크기에 더 가깝게 장애물을 판정한다.
- 도달 영역은 각 파워 샘플의 인접 각도 궤적 사이를 삼각형 Mesh로 채워 렌더링 호출 수를 줄이고, 입력 값과 씬 Collider 상태가 바뀔 때만 0.1초 간격으로 재계산한다.
- 파워 샘플 사이를 추가로 연결하던 Mesh 채움을 제거하고 파워 샘플 수를 늘려, 영역이 실제보다 지나치게 넓어 보이는 현상을 줄였다.
- 샘플 궤적이 하강 중 Platform 윗면과 만나고 Player 폭이 들어갈 수 있으면 착지 가능 구간과 후보 지점을 강조한다.
- 회전된 사각형 Platform은 실제 월드 꼭지점 기준으로 수평 윗변이 있는 경우에만 그 윗변을 착지 후보로 취급한다.
- 삼각형 Platform은 실제 꼭지점 기준으로 수평 윗변이 있는 경우에만 그 윗변을 착지 후보로 취급한다.
- 이 표시는 샘플 기반 제작 보조 기능이므로 실제 Play Mode 물리와 완전히 같은 연속 시뮬레이션은 아니지만, Rigidbody2D 감쇠와 장애물 Collider에 막히는 대표 구간을 반영한다.

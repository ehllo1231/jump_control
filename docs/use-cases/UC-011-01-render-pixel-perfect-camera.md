# UC-011-01: 픽셀 퍼펙트 카메라 렌더링

- 상태: Verified
- 마지막 갱신일: 2026-07-22

## 목적

플레이어가 서로 다른 가로 화면 해상도에서 게임을 실행해도 2D 카메라가 픽셀 아트의 정수 배율과 픽셀 격자를 유지하여 흔들림과 흐릿한 리샘플링을 줄인다.

## 액터

- 플레이어
- 개발자

## 사전 조건

- 활성 씬의 `Main Camera`에 Orthographic `Camera`와 `SimpleCameraFollow`가 연결되어 있어야 한다.
- 기본 픽셀 아트 기준은 16 PPU이고 기준 해상도는 `384 × 216`이다.

## 트리거

- 플레이어가 게임을 실행하거나 실행 중 화면 해상도가 변경된다.

## 기본 흐름

1. 시스템은 현재 화면 크기와 `384 × 216` 기준 해상도를 비교한다.
2. 시스템은 화면 안에 기준 해상도가 들어가는 가장 큰 1 이상의 정수 픽셀 배율을 계산한다.
3. 시스템은 16 PPU의 한 아트 픽셀이 계산된 정수 개수의 화면 픽셀에 대응하도록 Orthographic Size를 설정한다.
4. 시스템은 부드러운 플레이어 추적 결과를 화면 픽셀 격자에 맞춰 카메라의 X, Y 위치를 보정한다.
5. 플레이어는 픽셀 정렬을 유지하는 카메라로 게임을 플레이한다.

## 대안 및 예외 흐름

- 2a. 화면이 기준 해상도보다 작으면 시스템은 픽셀 배율을 1로 제한하고 표시 가능한 월드 영역만 렌더링한다.
- 2b. 화면 비율이 기준 해상도와 다르면 시스템은 기준 영역을 자르지 않는 정수 배율을 선택하고 남는 방향의 월드 영역을 추가로 표시한다.
- 3a. PPU 또는 기준 해상도 값이 유효 범위보다 작으면 시스템은 각 값을 최소 1로 보정한다.
- 4a. 픽셀 스냅이 비활성화되면 시스템은 Orthographic Size만 픽셀 배율에 맞추고 추적 위치는 보정하지 않는다.

## 인수 조건

- [x] `1920 × 1080`에서 픽셀 배율은 5이고 Orthographic Size는 `6.75`이다.
- [x] 지원 화면 크기에서 픽셀 배율은 항상 1 이상의 정수이다.
- [x] 카메라 X, Y 위치는 `1 / (16 × 픽셀 배율)` 월드 단위의 배수로 정렬된다.
- [x] 실행 중 화면 크기가 바뀌면 픽셀 배율과 Orthographic Size가 다시 계산된다.
- [x] 기존 플레이어 추적 오프셋, 추적 완화 시간, 최저 Y 제한과 카메라 Z 위치는 유지된다.
- [x] 씬 자동 생성 시 카메라의 기본 Orthographic Size가 `6.75`로 설정된다.

## 구현 메모

- `SimpleCameraFollow`가 화면 크기와 `384 × 216` 기준 해상도로 정수 픽셀 배율을 계산하고, 16 PPU 기준 Orthographic Size를 매 프레임 적용한다.
- 부드러운 추적 계산 뒤 카메라 X, Y만 `1 / (PPU × 픽셀 배율)` 월드 단위로 반올림하며 Z 위치는 변경하지 않는다.
- `MVPJumpScene`의 현재 카메라와 `MVPSceneBuilder`가 생성하는 카메라의 기본 Orthographic Size를 `6.75`로 통일했다.
- Unity 6000.3.1f1의 현재 프로젝트 컴파일 응답 파일로 런타임 및 에디터 어셈블리 컴파일을 통과했다.
- Unity 6000.3.1f1 임시 프로젝트에서 1080p·720p·기준보다 작은 화면의 픽셀 배율, 1080p Orthographic Size, X/Y 픽셀 스냅, Z 보존과 실제 Camera 컴포넌트 적용을 자동 검증했다.

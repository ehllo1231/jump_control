# UC-003-18: Stage1 Floor 시각 경계와 충돌 정렬

- 상태: Implemented
- 마지막 갱신일: 2026-07-26

## 목적

플레이어가 Stage1의 Floor에서 화면에 보이는 영역과 일치하는 충돌 판정을 경험한다.

## 액터

- 플레이어
- 맵 제작자
- 개발자

## 사전 조건

- `Assets/Scenes/MVPJumpScene.unity`의 `Stage1/Collision` 아래에 충돌 전용 `Floor`가 존재한다.
- `Stage1/ForegroundDecor/CollisionGuides` 아래에 Floor의 현재 외형을 표시하는 가이드가 존재한다.

## 트리거

- 플레이어가 Floor의 윗면, 좌우 끝 또는 아래쪽 경계에 접근한다.

## 기본 흐름

1. 시스템은 Floor 가이드의 월드 중심과 크기를 기준으로 시각 경계를 정한다.
2. 시스템은 충돌 전용 Floor의 `BoxCollider2D` 월드 경계를 시각 경계와 일치시킨다.
3. 플레이어는 화면에 보이는 Floor 영역 안에서만 Floor와 충돌한다.

## 대안 및 예외 흐름

- 1a. Floor와 가이드가 서로 다른 Transform 계층을 사용하면 시스템은 가이드의 월드 경계를 Floor의 로컬 좌표로 변환한다.
- 2a. 스프라이트의 피벗이 중앙이 아니면 시스템은 Renderer Bounds의 중심을 기준으로 Collider 오프셋을 정한다.

## 인수 조건

- [x] Floor `BoxCollider2D`의 월드 중심이 Floor 가이드의 SpriteRenderer 월드 중심과 일치한다.
- [x] Floor `BoxCollider2D`의 월드 크기가 Floor 가이드의 SpriteRenderer 월드 크기와 일치한다.
- [x] 보이는 Floor의 좌우 끝 바깥과 아래쪽에서 보이지 않는 Floor 충돌이 발생하지 않는다.
- [x] 보이는 Floor 윗면의 높이와 착지 높이가 유지된다.
- [x] 다른 Stage1 오브젝트와 Player 설정은 변경되지 않는다.

## 구현 메모

- 구현 전 직렬화 값을 계산한 결과, Floor 가이드의 월드 경계는 중심 `(4.2021, -3.4787)`, 크기 `(50.45023, 5.9966305)`인 반면 충돌체 경계는 중심 `(0, -500.4804)`, 크기 `(1000, 1000)`이었다.
- 두 경계의 윗면은 약 `0.000015` 월드 단위 오차로 정렬되어 있었지만, 충돌체가 가이드보다 좌우와 아래쪽으로 크게 돌출되어 있었다.
- 충돌 전용 Floor의 Transform을 보존하고 `BoxCollider2D` 로컬 offset을 `(0.0042021, 0.4970017)`, size를 `(0.05045023, 0.0059966305)`로 오버라이드했다.
- 씬 직렬화 값을 독립 계산해 Collider와 가이드의 월드 중심이 `(4.2021, -3.4787)`, 크기가 `(50.45023, 5.9966305)`로 일치하고 중심·크기 오차가 각각 `0`임을 확인했다.
- 프로젝트가 이미 다른 Unity Editor에서 열려 있어 별도 batchmode 씬 로드 검증은 실행하지 못했다.
